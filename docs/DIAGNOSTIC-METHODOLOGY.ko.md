# Owen MemTool 진단 방법론

## 판정 원칙

Owen MemTool은 메모리 사용량을 하나의 숫자로 해석하지 않습니다. 다음 순서로 원인을 좁힙니다.

1. 물리 메모리, 가용 메모리와 커밋 압박을 측정한다.
2. 프로세스 작업 집합과 사설 메모리 합계를 계산한다.
3. 프로세스로 설명되지 않는 비중을 커널 풀, 캐시와 GPU 문맥으로 분해한다.
4. 비페이징·페이징 풀의 절대값과 시간별 증가를 평가한다.
5. 파일시스템, 그래픽, 네트워크 드라이버와 실행 프로그램의 연관성을 찾는다.
6. CPU Interrupt/DPC와 프로세스 커널 핸들의 절대값·증가량을 평가한다.
7. 관측값과 추정 원인을 분리하고 확신 수준을 부여한다.
8. Pool Tag, 할당 스택 또는 A/B 테스트가 없으면 원인으로 확정하지 않는다.

## 주요 임계값

임계값은 1.0.0의 초기 휴리스틱이며 하드웨어 규모에 따라 동적으로 계산됩니다.

| 항목 | 검토 기준 | 위험 기준 |
|---|---:|---:|
| 사용 가능 메모리 | 물리 메모리의 15% 이하 | 7% 이하 |
| 커밋 | 커밋 한계의 75% 이상 | 90% 이상 |
| 비페이징 풀 | 1.5GB 또는 물리 메모리의 5% 중 큰 값 | 3GB 또는 10% 중 큰 값 |
| 페이징 풀 | 2GB 또는 물리 메모리의 8% 중 큰 값 | 별도 위험 기준 없음 |
| DWM 사설 메모리 | 1GB 이상이며 다중 디스플레이 또는 다중 GPU | 2GB 이상이면 주의 |
| CPU Interrupt/DPC | 둘 중 5% 이상 | 둘 중 15% 이상 또는 합계 20% 이상 |
| 전체 프로세스 핸들 | 5분간 5,000개 증가 또는 250,000개 이상에서 지속 증가 | 500,000개 이상 또는 20,000개 증가 |

## 지속 증가 판정

비페이징 풀 누수 가능성을 높이려면 다음 조건을 모두 만족해야 합니다.

- 관측 시간 5분 이상
- 총 증가량 64MB 이상
- 평균 증가율 분당 5MB 이상

시작값과 종료값만으로 순간 변동을 완전히 제거할 수 없으므로 결과는 `가능성 높음`까지입니다. `확정`은 Pool Tag 또는 할당 스택이 필요합니다.

## Synology Drive 규칙

다음 세 신호가 동시에 존재할 때만 후보를 생성합니다.

- 커널 풀이 경고 기준 이상
- `cbfltfs4` 또는 `cbfltfs4.sys` 실행
- Synology Drive 설치 또는 Synology Drive 프로세스 실행

이 규칙은 상관관계를 탐지합니다. `/n software` CallbackFilter가 실제로 해당 풀을 소유한다는 직접 증거는 아닙니다.

## DWM과 GPU 규칙

DWM 사설 메모리가 1GB 이상이고 활성 디스플레이 또는 GPU 어댑터가 둘 이상이면 그래픽 경로를 후보로 표시합니다. 다음 항목은 문맥으로만 사용합니다.

- GPU 전용·공유 메모리
- 활성 디스플레이 수
- 하이브리드 GPU 구성
- 그래픽 드라이버 버전

GPU 프로세스 카운터는 다중 어댑터 환경에서 같은 프로세스가 중복 집계될 수 있으므로 프로세스별 전용·공유 GPU 합계를 물리 메모리에 직접 더하지 않습니다.

## CPU 인터럽트와 DPC 규칙

`% Interrupt Time`, `% DPC Time`, `Interrupts/sec`, `DPC Rate`를 메모리 추세와 같은 간격으로 수집합니다. 비율 임계값을 넘으면 드라이버·하드웨어 경로 검토 finding을 만들지만, 실행 중인 드라이버 목록을 직접 원인으로 간주하지 않습니다. 원인 드라이버 확정에는 WPR/WPA의 ISR/DPC 스택이 필요합니다.

## 핸들 규칙

진단 시작과 종료에 프로세스 그룹별 핸들 합계를 수집하고 증가량 상위 그룹을 계산합니다. 5분 미만 결과는 현황 정보로만 사용하며 장기 증가 판정에 사용하지 않습니다.

이 카운터는 `File`, `Event`, `Key`, `Thread` 등을 포함한 모든 프로세스 커널 핸들입니다. 정확한 `File` 타입 핸들과 열린 경로는 Windows 기본 성능 카운터만으로 구분하지 않으며 Sysinternals Handle 또는 WPR이 필요합니다.

## 드라이버와 앱 연관 규칙

드라이버 파일 버전 정보, 디지털 서명, 설치 프로그램과 실행 프로세스를 제품명·벤더 규칙으로 연결합니다. 결과는 `연관 앱(추정)`이며 드라이버 서비스의 직접 소유권이나 메모리 할당 인과관계를 뜻하지 않습니다.

## 메모리 가시성 차이

다음 값은 설명 보조용입니다.

```text
물리 메모리 사용량 - 프로세스 작업 집합 합계
```

작업 집합에는 공유 페이지가 중복될 수 있고 전체 메모리에는 커널 풀, 파일 캐시, Standby 목록과 GPU 공유 메모리가 포함됩니다. 따라서 이 차이를 누수량으로 사용하지 않습니다.

## 점수와 정렬

각 원인은 심각도와 증거 수준에 따라 점수를 가지며 높은 점수부터 표시됩니다. 위험 수준은 가장 높은 점수를 기준으로 합니다.

- 95 이상: `Critical`
- 65 이상: `Review`
- 그 미만: `Healthy`

정보성 관측이 존재해도 위험 점수가 낮으면 전체 상태는 `Healthy`일 수 있습니다.

## 수집 데이터의 한계

- 일반 권한에서는 파일시스템 필터 목록과 Pool Tag 소유자를 완전히 확인할 수 없습니다.
- 시작·종료 값 기반 추세는 간헐적 급증의 정확한 시점을 보여주지 않습니다.
- 설치 프로그램과 드라이버의 동시 존재는 인과관계가 아닙니다.
- 드라이버와 연관 앱은 제품·벤더 규칙에 따른 추정이며 직접 소유 정보가 아닙니다.
- 전체 핸들 수에는 파일 외 커널 개체가 포함됩니다.
- 드라이버 할당은 사용자 프로세스 메모리에 나타나지 않을 수 있습니다.
- 재부팅 전후 기준값이 없으면 장기 누적과 정상 워크로드를 구분하기 어렵습니다.

## 안전 경계

진단 엔진은 드라이버, 서비스와 프로세스를 자동으로 제거하거나 비활성화하지 않습니다. 권장 조치는 증거를 추가로 확보하는 순서로 제시하며 파괴적인 조치는 직접 실행하지 않습니다.
