# Owen MemTool 사용 설명서

## 1. 도구의 목적

Owen MemTool은 Windows 작업 관리자의 전체 메모리 사용량만으로는 알기 어려운 다음 질문에 답하기 위한 도구입니다.

- 어떤 프로세스가 메모리를 많이 사용하고 있는가?
- 앱 사용량보다 전체 사용량이 훨씬 큰 이유는 무엇인가?
- 비페이징 풀이나 페이징 풀이 비정상적으로 큰가?
- DWM, 다중 GPU 또는 파일시스템 필터가 후보인가?
- CPU 인터럽트와 DPC가 비정상적으로 높은가?
- 특정 프로세스 그룹의 핸들이 관측 중 계속 증가하는가?
- 지금 증가 중인 누수인가, 과거에 누적된 메모리인가?

## 2. 실행 방법

저장소 루트에서 `Start-Owen-MemTool.cmd`를 더블클릭합니다. 검은 콘솔 창은 남지 않고 Owen MemTool 창만 열립니다.

명령줄에서 실행할 수도 있습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -STA `
  -File .\src\Owen-MemTool.ps1
```

이 실행은 관리자 권한을 요구하지 않습니다. 일반 권한에서도 프로세스, 주요 메모리 카운터, GPU, 실행 중인 드라이버와 설치 프로그램을 수집할 수 있습니다.

## 3. 진단 실행

### 관측 시간 선택

상단의 분할 버튼에서 관측 시간을 선택합니다.

| 시간 | 적합한 용도 | 한계 |
|---|---|---|
| 15초 | 빠른 현재 상태 확인 | 장기 누수 판정 불가 |
| 1분 | 앱 실행이나 작업 전후 비교 | 간헐적 드라이버 누수를 놓칠 수 있음 |
| 5분 | 커널 풀의 지속 증가 판정 | 진단 중 PC 사용 패턴을 일정하게 유지해야 함 |

### 진단 시작과 중지

**진단 시작**을 누르면 별도 PowerShell 프로세스가 데이터를 수집합니다. UI는 응답 상태를 유지하며 현재 단계와 진행률을 표시합니다.

관측 도중 **중지**를 누르면 수집 프로세스를 종료합니다. 완성되지 않은 보고서는 저장하지 않습니다. 이전에 완료한 보고서가 있으면 해당 결과 화면으로 돌아갑니다.

## 4. 진단 요약 화면

### 위험 수준

- **안정**: 경고 임계값을 넘는 항목이 없습니다.
- **검토 필요**: 드라이버, 프로세스 또는 메모리 압박을 점검해야 합니다.
- **즉시 확인**: 커밋 한계, 가용 메모리 또는 커널 풀이 위험 기준을 넘었습니다.

위험 수준은 가장 높은 점수의 원인을 기준으로 표시합니다. 특정 드라이버가 확정 원인이라는 뜻은 아닙니다.

### 핵심 지표

- **물리 메모리 사용**: Windows가 현재 사용 중인 물리 메모리입니다.
- **사용 가능**: 즉시 또는 빠르게 재사용할 수 있는 메모리입니다.
- **커널 풀**: 비페이징 풀과 페이징 풀의 합계입니다.
- **커밋**: 프로그램과 커널이 약속한 가상 메모리와 시스템 한계입니다.
- **Interrupt / DPC**: 하드웨어 인터럽트와 드라이버 지연 처리에 소비된 CPU 비율입니다.
- **프로세스 핸들**: 전체 프로세스 커널 핸들 합계와 관측 구간 변화량입니다.

### 추정 원인

원인 항목을 선택하면 오른쪽에 설명, 직접 관측된 근거와 다음 단계가 표시됩니다.

관련 드라이버가 있으면 이름, 벤더, 제품, 버전, 서명 상태, 실제 파일 경로와 `연관 앱(추정)`이 함께 표시됩니다. 설치 프로그램·실행 프로세스와 드라이버의 제품 또는 벤더 매핑이며 직접 소유 관계를 확정하는 정보는 아닙니다.

확신 수준을 반드시 함께 확인합니다.

- `관측됨`: 수치 자체는 직접 확인됨
- `추정`: 여러 정황의 상관관계
- `가능성 높음`: 5분 이상 지속 증가가 추가로 확인됨
- `확정`: 외부 정밀 도구나 A/B 테스트 필요

## 5. 프로세스 화면

같은 이름의 프로세스를 그룹으로 합쳐 보여줍니다. 예를 들어 VS Code는 여러 `Code.exe` 프로세스의 합계를 한 행에서 확인할 수 있습니다.

- **작업 집합**: 현재 물리 RAM에 올라온 페이지
- **사설 메모리**: 해당 프로세스만 사용하는 커밋 메모리
- **핸들**: 파일, 창, 이벤트, 레지스트리 키 같은 모든 커널 개체 참조 수
- **핸들 변화**: 진단 시작과 종료 사이 같은 프로세스 그룹의 핸들 증감

이 값은 파일 핸들만 센 수치가 아닙니다. 정확한 `File` 타입 핸들과 열린 경로를 확인하려면 Sysinternals Handle 또는 WPR/WPA가 필요합니다.

작업 집합 합계와 전체 물리 메모리를 단순 비교해 차이를 누수로 판정하면 안 됩니다. 공유 페이지, 커널 풀, 캐시와 GPU 메모리가 중복되거나 별도로 계산되기 때문입니다.

## 6. 드라이버 화면

실행 중인 파일시스템 드라이버와 서드파티 커널 드라이버를 표시합니다. 표에서 드라이버 이름, 벤더, 제품, 버전, 서명 상태, 실제 경로와 연관 앱(추정)을 확인할 수 있습니다.

다음 항목을 우선 확인합니다.

- 파일시스템 필터의 제품과 버전
- 그래픽·네트워크 드라이버 버전
- 부팅 시 자동으로 시작되는 드라이버
- 최근 설치 또는 업데이트된 드라이버
- 서명이 없거나 검증되지 않은 드라이버
- 제품·벤더 기준으로 연결된 설치 앱과 현재 실행 프로세스

이 목록에 나타난 것만으로 해당 드라이버가 누수 원인이라는 뜻은 아닙니다.

## 7. CPU 인터럽트와 핸들 해석

CPU 인터럽트 또는 DPC 시간이 5% 이상이면 드라이버나 하드웨어 경로를 검토할 후보로 표시합니다. 15% 이상이거나 두 값의 합이 20% 이상이면 즉시 확인 수준으로 올립니다. 순간 급증이 있을 수 있으므로 재현 가능한 작업에서 1분 또는 5분 진단으로 비교하십시오.

핸들은 5분 이상 관측했을 때 전체 증가량과 프로세스별 증가를 판정에 사용합니다. 전체 5,000개 이상 증가 또는 250,000개 이상에서 지속 증가하면 검토 후보이며, 500,000개 이상 또는 20,000개 이상 증가하면 위험 후보입니다.

ISR/DPC가 높다는 사실만으로 어느 드라이버가 원인인지 확정할 수 없습니다. 관련 드라이버 목록은 시스템 구성상 후보이며 확정에는 WPR/WPA 인터럽트·DPC 스택 분석이 필요합니다.

## 8. Synology Drive 후보를 해석하는 방법

Owen MemTool은 다음 조건이 동시에 맞으면 Synology Drive 파일시스템 필터를 후보로 표시합니다.

1. 비페이징 풀 또는 페이징 풀이 경고 기준을 넘음
2. `cbfltfs4.sys` CallbackFilter 드라이버가 실행 중임
3. Synology Drive가 설치되어 있거나 `cloud-drive-daemon`이 실행 중임

15초 또는 1분 진단에서는 확신 수준이 `추정`입니다. 5분 이상 비페이징 풀이 64MB 이상 증가하고 분당 5MB 이상의 증가율이 유지되면 `가능성 높음`으로 올라갑니다.

확정하려면 다음 중 하나가 필요합니다.

- PoolMon에서 증가하는 Pool Tag와 드라이버 매핑
- WPR/WPA의 커널 풀 할당 스택
- 재부팅 후 Synology Drive 활성·비활성 조건의 A/B 비교

`cbfltfs4.sys` 파일을 직접 삭제하지 마십시오. Boot 드라이버를 임의로 삭제하면 부팅이나 파일 접근에 문제가 생길 수 있습니다.

## 9. 보고서 열기

진단 요약의 **보고서 열기**는 Markdown 보고서를 메모장에서 엽니다. **보고서 폴더**는 `reports/`를 탐색기에서 엽니다.

보고서에는 다음 내용이 포함됩니다.

- 수집 시각과 관리자 권한 여부
- 핵심 메모리 지표
- 점수순 원인 목록
- 각 원인의 근거와 다음 단계
- 휴리스틱 해석 주의사항

## 10. 권장 진단 절차

1. 15초 진단으로 현재 상태를 확인합니다.
2. 비페이징 풀이 높으면 PC를 재부팅합니다.
3. 재부팅 10분 후 1분 진단으로 기준값을 저장합니다.
4. 평소 작업을 재현하면서 5분 진단을 실행합니다.
5. 두 Markdown 보고서에서 커널 풀과 후보를 비교합니다.
6. 지속 증가가 확인되면 PoolMon 또는 WPR/WPA로 소유자를 확인합니다.
7. 프로그램 제거·드라이버 롤백 같은 격리 테스트는 복원 지점을 확보한 뒤 수행합니다.

## 11. 문제 해결

### 창이 열리지 않는 경우

PowerShell 5.1과 WPF 어셈블리를 확인합니다.

```powershell
powershell.exe -NoProfile -STA -Command "Add-Type -AssemblyName PresentationFramework; 'WPF OK'"
```

### 진단이 실패하는 경우

- 다른 진단 프로그램이 성능 카운터를 독점하고 있지 않은지 확인합니다.
- Windows 성능 카운터 서비스가 정상인지 확인합니다.
- `reports/` 폴더에 쓰기 권한이 있는지 확인합니다.
- 저장소가 네트워크의 읽기 전용 위치에 있지 않은지 확인합니다.

### 관리자 권한이 필요한가?

기본 진단에는 필요하지 않습니다. PoolMon 기반 정밀 진단은 별도 도구 설치와 관리자 권한이 필요하지만 1.0.0 UI에서는 자동 실행하지 않습니다.

## 12. 개인정보와 보안

- 진단 데이터는 로컬 `reports/`에만 저장됩니다.
- 네트워크 업로드나 원격 분석 기능이 없습니다.
- 보고서에는 컴퓨터 이름, 프로세스 경로, 설치 프로그램과 드라이버 정보가 포함될 수 있습니다.
- 외부 공유 전 JSON과 Markdown에서 사용자 이름과 경로를 확인하십시오.
